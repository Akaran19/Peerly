# Fix the pipes, then open the taps

Peerly's best next step is to repair its four current integrations before adding new ones. OpenAlex moved to API keys and usage-based pricing in 2026. Crossref cut its anonymous rate limits in December 2025. The Semantic Scholar key is currently shipped inside the browser bundle. With those fixed, the highest-value additions are free, keyless and CORS-open, so they can be called from the browser today. They are: a retraction/correction banner built from Crossref and OpenAlex fields Peerly already downloads; free-PDF links from OpenAlex/Unpaywall and Europe PMC; DOAJ, ROR, OpenCitations, iCite and DataCite enrichment; and "Cite this paper" through doi.org content negotiation or client-side citation-js. A second wave needs a Supabase edge function: arXiv (no CORS, 1 request per 3 seconds globally), Semantic Scholar recommendations and SPECTER2 embeddings, ORCID sign-in, Zotero OAuth sync, OpenAlex semantic search, Claude-powered summaries and Resend email. Altmetric, PlumX, Dimensions and Sherpa Romeo should be deferred. Each is paid, key-gated or non-commercial, and Peerly will become a revenue-generating product once its pricing work finishes. The same non-commercial clauses also apply to two APIs that look free: ORCID's Public API and parts of Semantic Scholar's data. Peerly should resolve them before it launches paid tiers.

## Four existing integrations are already out of date

**OpenAlex is no longer a free, keyless API.** Each free API key gets **$1 of usage per day**. Keyless callers get **$0.10/day**. Lookups of a single work by ID or DOI are free, list/filter calls cost $0.10 per 1,000, search costs $1 per 1,000, and PDF content downloads cost $10 per 1,000 ([OpenAlex Pricing](https://help.openalex.org/access/pricing.md); [OpenAlex example costs](https://help.openalex.org/access/example-costs.md)). Rate limits are 10 req/s without a key, 30 with a free key and 50 on annual plans. Without a key, cursor paging returns only the first page. The docs say to keep the key in an `OPENALEX_API_KEY` environment variable rather than in shared code ([OpenAlex Authentication](https://help.openalex.org/api/authentication.md)). A code check shows `src/lib/crossref.ts` calls OpenAlex keyless from the browser in three places: a single-work lookup (free), a `filter=cites:` list with `per-page=200` (billable, and paging is cut off without a key), and a keyword `search=` (the expensive tier). The single-work lookup in `src/pages/ExternalPaperResolverPage.tsx` can stay in the browser. The search and `cites:` list calls should move into a Supabase edge function that adds the key and caches results in Postgres. The old "`mailto=` polite pool, 100k calls/day" model is gone. The documentation has also moved from docs.openalex.org to help.openalex.org ([OpenAlex llms.txt](https://help.openalex.org/llms.txt)).

**Crossref's December 2025 limits put Peerly's browser calls in the slowest pool.** Since 1 December 2025, the public pool allows **5 req/s for single records and 1 req/s for list queries**. The polite pool, reached by adding a `mailto=` parameter, allows 10 and 3 ([Crossref blog](https://crossref.org/blog/announcing-changes-to-rest-api-rate-limits/)). Live response headers confirmed the change: `x-rate-limit-limit: 5` without a `mailto`, 10 with one ([Crossref works API](https://api.crossref.org/works/10.1038/nature12373)). Peerly tries to identify itself through a `User-Agent` header set to `PaperLog/1.0 (mailto:contact@example.com)`. That has two problems: the address is a placeholder, and browsers generally do not let page scripts override `User-Agent`. Crossref therefore sees an anonymous caller. The fix is one line: add `&mailto=<real Peerly ops address>` to every Crossref URL. Back off on HTTP 429. Run any batch job, such as the retraction sweep below, server-side in the polite pool.

**The Semantic Scholar key is exposed, and its proxy likely only works in development.** `VITE_S2_API_KEY` uses the `VITE_` prefix, so Vite compiles it into the public JavaScript bundle. The `/api/semanticscholar` proxy is defined only in `vite.config.ts` (the dev server). The repository has no `/api` Vercel function, and `vercel.json` excludes `/api/` from its SPA rewrite. Unless something is deployed elsewhere, production calls to that path return 404, and Semantic Scholar enrichment quietly fails. This matters because keys are scarce. Since August 2024, Semantic Scholar has stopped approving keys for free email domains or "third-party apps", it prunes keys that are idle for about 60 days, and new keys get **1 RPS on all endpoints** ([allenai/s2-folks release notes](https://github.com/allenai/s2-folks/blob/main/API_RELEASE_NOTES.md); [Semantic Scholar API](https://www.semanticscholar.org/product/api)). A leaked key that is abused could be revoked with no replacement available. Peerly should move the key into a Supabase secret and route Semantic Scholar through an edge function. It should also rotate the key, because the old one has already shipped in the bundle.

**PMC and bioRxiv changed underneath every biomedical integration.** NCBI shut down the **PMC OA Web Service** (`oa.fcgi` now returns 404) and removed the legacy FTP packages in August 2026 ([PMC OA Service](https://pmc.ncbi.nlm.nih.gov/tools/oa-service/); [NLM Technical Bulletin](https://www.nlm.nih.gov/pubs/techbull/jf26/jf26_Changes_to_PMC_ArtDsDistribServs_2026.html)). The replacement is a free, login-free AWS bucket. Each article has a JSON file containing `pdf_url` and `xml_url` ([PMC AWS README](https://pmc-oa-opendata.s3.amazonaws.com/README.txt)). The PMC ID Converter moved to `pmc.ncbi.nlm.nih.gov/tools/idconv/api/v1/articles/`, and the old URL now 301-redirects. Separately, bioRxiv and medRxiv preprints posted since **1 December 2025 use the DOI prefix `10.64898`**, not `10.1101` ([openRxiv](https://connect.biorxiv.org/news/2025/11/18/preprint_dois)). Peerly's code has no `oa.fcgi` or hard-coded `10.1101` references today, so nothing is broken yet. Any new preprint-detection regex has to accept both prefixes. The PubMed E-utilities URL in `PMIDResolverPage.tsx` puts a personal Gmail address in a client-visible query string, which should change to a project contact address.

## Ten keyless, browser-safe sources make the first wave

These sources have three things in common. Live probes with `Origin: https://peerly.io` returned permissive CORS headers. None needs a key. All have open or CC0-style data terms. They fit Peerly's existing pattern of calling APIs directly from React, although caching in Postgres is still advisable because limits are per IP.

**Retraction and correction banners cost nothing new.** On a retracted paper's own Crossref record, `GET /works/{doi}` returns an `updated-by[]` array. For the Wakefield Lancet paper, that array contains `{type:"retraction", source:"retraction-watch", DOI, updated}` plus an earlier `correction` ([Crossref works API](https://api.crossref.org/works/10.1016/S0140-6736(97)11096-0)). Retraction Watch data is merged into Crossref and also published as a daily CSV ([Crossref RW docs](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch/)). OpenAlex exposes `is_retracted`, which returns `true` for the same paper even though it still has **3,009 citations** ([OpenAlex](https://api.openalex.org/works/doi:10.1016/S0140-6736(97)11096-0?select=id,is_retracted,cited_by_count)). Peerly already downloads both payloads, so the banner only needs parsing and UI. It can be graded: retracted, expression of concern, or corrected. Records do get revised: one changed from "retraction" to "expression of concern" in March 2026 ([Crossref community](https://community.crossref.org/t/api-retraction-status-not-confirmed-at-retractiondatabase-org/15831)). Crossref has no filter that returns retracted originals directly ([same thread](https://community.crossref.org/t/api-retraction-status-not-confirmed-at-retractiondatabase-org/15831)). To alert users who shelved a paper that is later retracted, mirror the daily CSV into Postgres with `pg_cron`. For a site where users rate and review papers, this is the strongest trust feature available, and the data is free.

**Free-PDF links should come from fields Peerly already fetches.** Unpaywall and OpenAlex have shared one database since late 2025. Unpaywall's `best_oa_location.url_for_pdf` is the same data as OpenAlex's `best_oa_location` ([OpenAlex help: Unpaywall](https://help.openalex.org/access/unpaywall.md)). Peerly already reads Semantic Scholar's `openAccessPdf`. Reading OpenAlex's `best_oa_location` from the free single-work lookup gives Unpaywall-grade coverage with no new provider. Use Unpaywall directly (`api.unpaywall.org/v2/{doi}?email=`) only as a fallback. It rejects placeholder emails with HTTP 422, covers only Crossref DOIs, and returns `"deprecated"` in its `evidence` and `updated` fields. For biomedical papers, the **Europe PMC REST API** adds direct OA PDF URLs, licence and `hasPDF` flags, and full-text XML, with no auth. Its `SRC:PPR` filter is the only single, CORS-open keyword search across preprint servers: 76,572 preprints with full text on 2026-10-23 (live probe, [Europe PMC search](https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=SRC:PPR%20AND%20HAS_FT:Y&format=json)). bioRxiv's own API has no keyword search. Its `/pubs` endpoint maps a preprint to its published version, which supports a "this preprint was published as..." link on shelves ([api.biorxiv.org](https://api.biorxiv.org/)).

**Journal, institution and citation enrichment is all open data.** **DOAJ** (`/api/search/journals/issn:{issn}`) returns APC, licence, review process, plagiarism and preservation policy. That is enough for an "in DOAJ" legitimacy badge. It is limited to 2 req/s, journal data is **CC BY-SA 4.0** (attribution and share-alike if redistributed) and article data is CC0 ([DOAJ API docs](https://doaj.org/api/docs); [DOAJ terms](https://doaj.org/terms)). **ROR** v2 supplies institution chips with country, links and Wikidata cross-IDs. It is free with no registration, but a 2024 proposal would cut anonymous callers to 50 requests per 5 minutes unless they send a client ID ([ROR blog](https://ror.org/blog/2024-08-29-api-client-identification/)). **OpenCitations** offers CC0 citation and reference lists and counts at 180 req/min per IP. Note that it returns the count as a string ([OpenCitations Index v2](https://api.opencitations.net/index/v2)). **NIH iCite** returns field-normalized Relative Citation Ratio, NIH percentile and translational flags (`apt`, `is_clinical`) for PMIDs Peerly already resolves. Batches fail above roughly 1,000 PMIDs ([iCite API](https://icite.od.nih.gov/api/pubs?pmids=23456789)). **DataCite** covers the datasets and software DOIs that Unpaywall and Crossref miss, including view and download counts and linked datasets ([DataCite API](https://api.datacite.org/dois/10.5061/dryad.8515)).

**"Cite this" and library import need no backend.** `GET https://doi.org/{doi}` with `Accept: text/x-bibliography; style=apa` returns a formatted citation. It also serves BibTeX, RIS and CSL-JSON, and accepts any CSL style name ([DOI Citation Formatter](https://citation.doi.org/docs.html)). A live test showed doi.org and its Crossref redirect both send CORS headers. For whole-library export, each request would count against Crossref's 5 req/s limit. The better route is to map stored rows to CSL-JSON and render locally with MIT-licensed **citation-js**. Its BibTeX and RIS plugins also parse uploaded `.bib` and `.ris` files ([citation-js](https://github.com/citation-js/citation-js)). Parsing uploads covers Mendeley, Paperpile and EndNote users at once, because none of the three offers a usable public web API ([EndNote community](https://community.endnote.com/t/endnotes-web-api/387005); [Mendeley dev portal](https://dev.mendeley.com/)). **Zotero** is the exception: `api.zotero.org` is fully CORS-open, with `format=csljson|bibtex|ris` exports ([Zotero Web API v3](https://www.zotero.org/support/dev/web_api/v3/basics)). A first version can be "paste your Zotero API key and user ID" for a read-only import.

## An edge-function proxy unlocks the second wave

Peerly already runs Deno edge functions (`clerk-webhook`, `gdpr-data`), so a third `paper-proxy` function is a small step. These integrations need one for one of three reasons: no CORS, a secret that must stay server-side, or a rate limit that is global across all Peerly users.

**arXiv** sends no CORS header and limits callers to **one request every three seconds, one connection at a time**, across every machine you control. Its metadata is CC0, but PDFs should be linked, not re-hosted ([arXiv API ToU](https://info.arxiv.org/help/api/tou.html)). It needs a serialized, cached proxy. Several blog posts claimed in October 2026 that arXiv tightened its API limits. They misread a policy about *submissions* ([arXiv blog](https://blog.arxiv.org/2026/10/01/updated-rate-limit-policy/)). **Semantic Scholar recommendations** (`POST /recommendations/v1/papers/` with positive and negative seed IDs, up to 500 results) drive "because you read X" from a user's high- and low-rated shelf ([wrapper source](https://glama.ai/mcp/servers/@zongmin-yu/semantic-scholar-fastmcp-mcp-server/blob/main/semantic_scholar/api/recommendations.py)). They should run as a nightly batch cached for about 7 days, because the 1 RPS key is shared by every user. The same key can pull 768-dimension SPECTER2 embeddings to seed a pgvector table. Alternatively, Supabase's built-in `gte-small` model generates embeddings in-process at no cost ([Supabase embeddings](https://supabase.com/docs/guides/ai/quickstarts/generate-text-embeddings)). The recommended architecture is hybrid. Hosted APIs (Semantic Scholar recommendations, OpenAlex `related_works`) generate candidates. A user taste vector, built as a rating-weighted average of shelf embeddings, re-ranks them in Postgres. **OpenAlex semantic search** (`search.semantic=`, GTE-Large 1024-dimension embeddings) is capped at **1 req/s and 50 results**, at $1 per 1,000 calls ([OpenAlex semantic search](https://help.openalex.org/api/semantic-search.md)). That suits a cached "search by meaning" mode, not autocomplete.

**ORCID sign-in** gives verified-author badges and lets authors claim papers. ORCID is a standard OIDC provider: the `openid` scope returns the ORCID iD as `sub` ([ORCID OIDC discovery](https://orcid.org/.well-known/openid-configuration)). Whether Clerk accepts it as a custom OIDC provider is unverified. The fallback is a "link ORCID" flow after Clerk sign-in, with the token exchange done in the edge function. The registered Public API allows 12 req/s and 100k reads/day ([ORCID limits](https://info.orcid.org/ufaqs/what-are-the-api-limits/)). **Zotero two-way sync** uses OAuth 1.0a with HMAC-SHA1 signing, so it must run server-side ([Zotero OAuth](https://www.zotero.org/support/dev/web_api/v3/oauth)). **Claude** for "explain this abstract" and review assistance must run behind an edge function that verifies the Clerk JWT, enforces a per-user quota and caches each paper's summary once. At Anthropic's current list price for Haiku ([Anthropic pricing](https://docs.claude.com/en/docs/about-claude/pricing)), a 1,500-token-in, 300-token-out call costs a fraction of a cent. Since 21 October 2026, sending `temperature`/`top_p`/`top_k` returns a 400, so do not copy older sample code that sets them. **Resend** handles review notifications and weekly digests. Its free tier is 3,000 emails/month, capped at 100/day, then $20/month for 50k ([Resend pricing](https://resend.com/pricing)). **SendGrid retired its free plan in May 2025**, so guides that recommend it as free are out of date ([Twilio changelog](https://www.twilio.com/en-us/changelog/sendgrid-free-plan)). **CORE** adds long-tail repository full text. Full text requires a key, and anonymous callers get 100 tokens/day ([CORE API v3](https://api.core.ac.uk/docs/v3)), so add it only if the PDF fallbacks above leave visible gaps.

| **Semantic Scholar** | Live, 1 RPS keys | No repackaging; some data CC BY-NC; terminable "for any reason" ([S2 licence](https://www.semanticscholar.org/product/api/license)) | Use now, get an AI2 agreement before paid tiers. Prefer CC0 OpenAlex for stored abstracts |
| **ORCID Public API** | Live, free | "may not make use of the public APIs in connection with any revenue-generating product" ([ORCID terms](https://info.orcid.org/public-client-terms-of-service/)) | Use while free; budget for membership at monetization |
| **DOAJ journal data** | Live | CC BY-SA 4.0: attribution and share-alike on redistribution | Attribute; don't bulk-republish |
| **PMC Cloud / arXiv** | Live | Link, don't re-host; credit NLM; no implied endorsement ([PMC README](https://pmc-oa-opendata.s3.amazonaws.com/README.txt)) | Link out only |
| **OpenAlex, OpenCitations, Crossref, DataCite metadata** | Live | CC0 / open | Safe base layer |

The pattern is clear. The metric that looks best on a paper page, an attention score, is the one most tightly licensed against consumer apps. Zenodo removed its Altmetric badges in 2020 when the free tier ended ([Zenodo blog](https://blog.zenodo.org/page/8)). Two other tools remain deferred for cost reasons rather than licensing. Zotero translation-server (URL to metadata) and GROBID (PDF to metadata) are both Docker services that cannot run inside a Supabase edge function. GROBID needs several GB of RAM ([GROBID docs](https://grobid.readthedocs.io/en/latest/Grobid-service/); [translation-server](https://github.com/zotero/translation-server)). Defer them until users actually ask for "paste any URL" or PDF upload. Connected Papers, ResearchRabbit and Litmaps publish no developer API. Build a co-citation graph yourself from OpenAlex and Semantic Scholar references, or add deep-link buttons.

## Conclusion

Peerly's integration risk now comes mostly from policy and pricing changes, not from missing features. In the past year, OpenAlex, Crossref, Semantic Scholar, Altmetric, SendGrid and NCBI each changed rules in ways that quietly break browser-only code: a bundled key, a keyless list query, a placeholder `mailto`. The lasting lesson is architectural. Peerly needs one cached edge-function gateway that holds every key and contact email and absorbs every global rate limit. Browser calls should be reserved for free singleton lookups and CORS-open open data. That gateway makes later integrations cheaper, and each one becomes a configuration change.

The second implication is commercial. The free sources most valuable to a review-centric product (retraction status, OA links, CC0 metadata, citation counts) are also the ones with the cleanest licences. The tempting extras (attention scores, scite stances, Semantic Scholar TLDRs, ORCID data) all have non-commercial or unpublished terms that take effect the day Peerly charges money. The pricing work under way in the codebase should therefore include an API-licence review, especially for ORCID membership and a Semantic Scholar agreement. Some facts remain unverified: Clerk's support for ORCID as a custom provider, scite's terms, ROR's current anonymous limit, iCite's documented batch cap, and the exact path of the Semantic Scholar recommendations endpoint. Check each before building on it.
